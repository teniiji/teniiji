# 6. แผนงานเป็นระยะ (Roadmap)

การเรียงลำดับเฟสยึดหลัก "โมดูลที่โมดูลอื่นต้องพึ่งพาก่อน" — โมดูล 1 (เงินฝาก-หุ้น-เงินกู้) เป็นแกนข้อมูลที่โมดูลอื่นทั้งหมดอ้างอิงถึง จึงต้องเสร็จก่อนเสมอ

## Phase 1 — MVP

**เป้าหมาย**: เจ้าหน้าที่เลิกใช้ Excel แยกไฟล์สำหรับงานแกนหลัก สมาชิกเห็นยอดของตัวเองได้

- ทะเบียนสมาชิก (ข้อมูลพื้นฐาน, สถานะสมาชิกภาพ)
- ระบบยืนยันตัวตน/สิทธิ์การเข้าถึงพื้นฐาน (RBAC ฝั่งเจ้าหน้าที่, LINE Login ฝั่งสมาชิก)
- โมดูล 1: เงินฝาก-หุ้น-เงินกู้ของสมาชิก (บันทึกธุรกรรม, ตารางผ่อนชำระ, ดูยอดคงเหลือ)
- Audit log พื้นฐานสำหรับธุรกรรมการเงิน

## Phase 2

**เป้าหมาย**: ขยายไปสู่สวัสดิการและการมองเห็นภาพรวมสำหรับผู้บริหาร

- โมดูล 2: สวัสดิการและเงินสงเคราะห์ (ทะเบียนกองทุน, คำขอรับสิทธิ, เวิร์กโฟลว์อนุมัติ)
- โมดูล 3: รายงานผู้บริหาร/การเงิน (งบดุล, งบกำไรขาดทุน, รายงานหนี้ค้างชำระ, แดชบอร์ด, คำนวณเงินปันผล/เฉลี่ยคืน)

*เหตุผล*: โมดูล 3 ต้องการข้อมูลธุรกรรมที่สมบูรณ์จาก Phase 1 จึงจะออกรายงานได้ถูกต้อง ส่วนโมดูล 2 เป็นส่วนขยายที่ไม่ผูกกับโมดูล 3 โดยตรง จึงพัฒนาคู่ขนานกันได้

## Phase 3

**เป้าหมาย**: ลดภาระงานเจ้าหน้าที่ด้านการสื่อสารและกระทบยอด ซึ่งเป็นงานที่ซับซ้อนกว่าและขึ้นกับรูปแบบไฟล์จากภายนอกที่ต้องยืนยันก่อน

- โมดูล 4: แจ้งเตือน/สื่อสารกับสมาชิก (LINE OA/LIFF push, SMS สำรอง)
- โมดูล 5: นำเข้า/กระทบยอด statement (ไฟล์หักเงินเดือนต้นสังกัด, statement ธนาคาร, รายการโอนตรงจากสมาชิก)

*เหตุผล*: โมดูล 4 ได้ประโยชน์สูงสุดเมื่อมีข้อมูลธุรกรรม (Phase 1) และสวัสดิการ (Phase 2) ให้แจ้งเตือนแล้ว ส่วนโมดูล 5 ต้องพึ่งพา `PayrollDeductionRecord` และ `Transaction` ที่มีอยู่แล้วจึงจะกระทบยอดได้ อีกทั้งยังรอการยืนยันรูปแบบไฟล์จริงจากต้นสังกัด/ธนาคาร (ดู [07-ข้อสมมติฐานที่ต้องยืนยัน.md](07-ข้อสมมติฐานที่ต้องยืนยัน.md)) จึงเหมาะเป็นเฟสหลังสุดเพื่อให้มีเวลาเก็บตัวอย่างไฟล์จริงมาออกแบบ

## Phase 4+ (อนาคต)

- Native mobile app (หากพบว่า LIFF ไม่เพียงพอต่อความต้องการ)
- การเชื่อมต่อ API กับหน่วยงานภายนอกโดยตรง (เช่น รับไฟล์หักเงินเดือนแบบอัตโนมัติแทนการอัปโหลดมือ)
- Business intelligence ขั้นสูง/การพยากรณ์ความเสี่ยงหนี้ด้วยข้อมูลย้อนหลัง
