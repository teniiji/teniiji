# 7. ข้อสมมติฐานที่ต้องยืนยัน

เอกสารชุดนี้จัดทำจากความรู้ทั่วไปเกี่ยวกับการดำเนินงานของสหกรณ์ออมทรัพย์ครูในประเทศไทย ก่อนเริ่มพัฒนาจริงควรตรวจสอบและยืนยันประเด็นต่อไปนี้กับสหกรณ์ออมทรัพย์ครูหนองคาย จำกัด โดยตรง

## ยืนยันแล้ว

- **"Statement bank" (โมดูล 5)** หมายถึงการนำเข้า/กระทบยอดข้อมูลจาก 3 แหล่ง: (1) ไฟล์หักเงินเดือนจากต้นสังกัด (2) statement จากธนาคาร (3) รายการโอนเงินตรงจากสมาชิก (เช่น สมาชิกเกษียณที่ไม่มีเงินเดือนให้หัก)
- **กลุ่มผู้ใช้เป้าหมาย**: ทั้งฝั่งเจ้าหน้าที่สหกรณ์ (back office) และฝั่งสมาชิก (self-service)
- **ลำดับความสำคัญของโมดูล**: เงินฝาก-หุ้น-เงินกู้ → สวัสดิการ/เงินสงเคราะห์ → รายงานผู้บริหาร/การเงิน → แจ้งเตือน/สื่อสาร → นำเข้า/กระทบยอด statement
- **รูปแบบเอกสาร**: แยกเป็นหลายไฟล์ตามหัวข้อในโฟลเดอร์ `docs/design/`

## ยังต้องยืนยันก่อนเริ่มพัฒนาจริง

1. **ระบบเดิมที่ใช้งานอยู่** — ปัจจุบันสหกรณ์ใช้ระบบ back office/Excel/โปรแกรมสำเร็จรูปใดอยู่หรือไม่ ถ้ามี ต้อง migrate ข้อมูลหรือเชื่อมต่อ (integrate) หรือไม่
2. **รูปแบบไฟล์หักเงินเดือนจริง** — ไฟล์จากต้นสังกัด (เขตพื้นที่การศึกษา/สพฐ./กรมบัญชีกลาง) เป็นรูปแบบใด (CSV/Excel/fixed-width) มีกี่ต้นสังกัดที่ต้องรองรับพร้อมกัน และคอลัมน์ข้อมูลมีอะไรบ้าง
3. **รูปแบบ statement ธนาคาร** — ธนาคารที่สหกรณ์ใช้งานจริง (เช่น กรุงไทย, ธ.ก.ส., อื่นๆ) และรูปแบบไฟล์ที่ธนาคารรองรับการส่งออก (มี API หรือต้องดาวน์โหลดไฟล์ด้วยมือ)
4. **ผังบัญชีและรูปแบบรายงาน** — ผังบัญชีและรูปแบบรายงานทางการเงินที่นายทะเบียนสหกรณ์/กรมตรวจบัญชีสหกรณ์กำหนด อาจมีรายละเอียดเฉพาะที่ต่างจากมาตรฐานทั่วไปที่ใช้ในเอกสารนี้
5. **ระเบียบสวัสดิการและเงินสงเคราะห์เฉพาะของสหกรณ์** — เงื่อนไขสิทธิ์ อัตราเงินสงเคราะห์ และหลักเกณฑ์ทุนการศึกษาที่ใช้จริงของสหกรณ์ออมทรัพย์ครูหนองคาย
6. **ขอบเขตช่องทางของ MVP** — เปิดตัวเว็บ back office ก่อนแล้วค่อยตามด้วย LINE LIFF หรือเปิดพร้อมกันทั้งสองฝั่งตั้งแต่ MVP
7. **จำนวนสมาชิกและปริมาณธุรกรรมจริง** — เพื่อประเมินขนาดโครงสร้างพื้นฐานและงบประมาณที่เหมาะสม
